# Elicit Platform — Requirements Catalog (Umbrella)

Source: [`docs/vision.md`](vision.md), the three modules' `application.properties`,
`docker-compose.yml`, `DeploymentScript.md`, the `elicitsoftware/elicit_db` image's
init scripts, [`docs/BRAND_SYSTEM_IMPLEMENTATION_GUIDE.md`](BRAND_SYSTEM_IMPLEMENTATION_GUIDE.md),
[`docs/I18N_IMPLEMENTATION_GUIDE.md`](I18N_IMPLEMENTATION_GUIDE.md), and the module
use cases this manual provisions for (Admin UC-027, UC-028; Author UC-041; Survey UC-007).

This catalog covers the **umbrella repository only** — the platform as one
deployable whole. Each module keeps its own catalog for its own behavior; module
requirement IDs are unrelated to the IDs here.

Roles referenced below:

- **Deployment Operator** — the primary actor; installs and configures an Elicit
  site. Comfortable with PostgreSQL, containers or a JVM service manager, and an
  OIDC provider; has not seen Elicit before.
- **Release Engineer** — builds and stamps the manual as part of a release.
- **Survey Administrator** / **Survey Author** — secondary actors; they take over
  where this manual stops, through their own manuals.

## Constraints

| ID    | Title                         | Constraint                                                                                                                                                                                                                                 | Category   | Priority | Status |
|-------|-------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------|----------|--------|
| C-001 | Umbrella Holds No Source      | The manual and its build script live in the umbrella repository, which holds no application source. The manual must not be packaged into, or served by, any module image.                                                                   | Technical  | High     | Open   |
| C-002 | Typesetting Toolchain         | The manual is written in LaTeX and typeset with LuaLaTeX through `latexmk` inside a TeX Live container, matching `Author/docs/manual/build-manual.sh`.                                                                                       | Technical  | High     | Open   |
| C-003 | Shared Brand Package          | The manual uses the same `elicit-brand.sty` design as the author's manual — the same colors, typefaces, page furniture and call-out boxes — so that the two documents read as one set.                                                      | Technical  | Medium   | Open   |
| C-004 | Scope Is Provisioning         | The manual covers provisioning a deployment. Operating the console is the administrator's manual (Admin UC-029) and building a survey is the author's manual (Author UC-039); the installation manual points at them and stops.            | Business   | High     | Open   |
| C-005 | Three Applications            | The configuration reference covers Survey, Admin and Author. FHHS and Pedigree appear only where Survey, Admin or Author must be configured to reach them.                                                                                   | Business   | High     | Open   |
| C-006 | Upgrades Stay in DeploymentScript | Release-specific upgrade procedures stay in `DeploymentScript.md`. The manual points at them and must not restate them, because a stamped manual outlives the release it was built for.                                                 | Business   | High     | Open   |
| C-007 | Database Platform             | PostgreSQL 17, matching `quarkus.datasource.db-version` in all three modules.                                                                                                                                                               | Technical  | High     | Open   |
| C-008 | Runtime Platform              | Java 25 and Quarkus 3.39.2, matching the four Java modules.                                                                                                                                                                                 | Technical  | High     | Open   |
| C-009 | Identity Provider             | Authentication is OIDC. The manual must describe the clients and roles in provider-neutral terms, using Keycloak only as the worked example the repository ships.                                                                            | Technical  | High     | Open   |
| C-010 | Access Code Terminology       | The credential a respondent enters to reach a survey is the **access code**. "Token" means only a question-text placeholder or an OIDC/Bearer token, and the manual must not use it for the respondent credential.                           | Business   | High     | Open   |
| C-011 | No Prometheus Service         | The compose file runs no Prometheus service and nothing scrapes `/q/metrics`. The manual documents the metrics endpoints as endpoints a site may scrape, and must not describe a metrics stack this repository does not run.                | Technical  | Medium   | Open   |
| C-012 | Language Management Is Server-Side | Adding, replacing and removing a language is a server-side file operation today. The in-application Languages screens (Admin UC-027, Author UC-041) are specified and not implemented; the manual documents the file procedure as the operative one. | Technical  | High     | Open   |
| C-013 | Read-Only Mounts              | The brand and translations directories are mounted read-only in `docker-compose.yml`. A deployment that intends to use the specified in-application language management will have to mount the translations directory writable (Admin C-015, Author C-024). | Technical  | Medium   | Open   |
| C-014 | License                       | The codebase is governed by the PolyForm Noncommercial 1.0.0 license, and the manual carries the same notice.                                                                                                                                | Regulatory | High     | Open   |
