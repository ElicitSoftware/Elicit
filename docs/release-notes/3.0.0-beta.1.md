# Elicit 3.0.0 Beta 1 — Release Notes

**Release date:** _to be set when tagged_
**Supersedes:** 2.2.0
**Modules in this release:** Survey 3.0.0-beta.1, Admin 3.0.0-beta.1, FHHS 3.0.0-beta.1,
Pedigree 3.0.0-beta.1, and this umbrella repository (compose file, scripts, installation manual).

This is a **beta**. It is feature-complete for 3.0.0 and has passed the full
build, the module test suites, and both a greenfield (empty database) and a brownfield
(upgraded 2.x database) run of the local stack, including a respondent round trip. Run it in a
test environment before production. It has not been through a production rollout yet.

Survey, Admin and FHHS share one database and **must be upgraded together from this
release**. A 3.0.0 module against a 2.x database, or the other way round, will not start.
Take a database backup before upgrading: no module ships a down-migration, so the backup is the
only way back.

---

## Highlights

- **Versioned survey definitions (Kimball Type 2).** Every structural survey table (steps,
  sections, questions, relationships and others) now keeps its history as effective-dated rows
  with durable keys. Respondents' answers stay tied to the version of the survey they actually
  saw, and a revised definition can be applied over an existing survey (Admin UC-017).
- **One reporting schema per survey.** Each survey gets its own star schema, named
  `report_<survey name>` (for the Family History Survey, `report_family_history_survey`) and
  recorded on `survey.surveys.report_schema`. It is built when the survey definition is applied,
  with no restart needed, and can be renamed from the Admin console.
- **Multilingual.** The Survey and Admin interfaces can be offered in any language a site
  mounts. ElicitSoftware ships a curated set beside the release: Latin American Spanish (`es-419`)
  and Arabic (`ar`, right to left), in `elicit-i18n/`. The images themselves carry English only.
  Survey content can be translated too: the translations travel in the `.elicit` file and are
  shown in the respondent's language.
- **Access codes.** The respondent's credential is now called an *access code* everywhere:
  database, configuration, API, email templates and branding. This is a breaking rename; see
  [Breaking changes](#breaking-changes).
- **Admin console additions:** a Participation page, a System section, the administrator's
  manual, export of a survey definition, and department assignment.
- **Security hardening:** outbound TLS is now verified, outbound calls have timeouts, SFTP
  host keys are checked, SVG rendering no longer fetches external resources, and database
  passwords are no longer built in.

## Breaking changes

Read these before upgrading. The step-by-step procedures are in `DeploymentScript.md`.

### Database and deployment

- **Upgrade Survey, Admin and FHHS together.** Survey has to finish its migrations before
  Admin and FHHS start. Docker Compose handles this through `depends_on` and health checks; a
  deployment without Compose must start Survey first and wait for it to be ready. FHHS starts
  after Admin.
- **The old reporting schema is dropped and rebuilt.** Survey's V021 drops the reporting tables
  in `surveyreport`, leaving only `dim_date` and `dim_status`, and rebuilds each survey's star
  from `survey.answers` in its own schema. What changes for report consumers:
  - **Schema name.** Queries and BI connections that read `surveyreport.fact_sections_view`
    must read `<report_schema>.fact_sections_view` instead.
  - **Ids.** `fact_sections.id` and every `dim_*.id` get new values. Extracts keyed on them
    must be pulled again.
  - **Corrected columns.** `fact_sections.step_key` and `section_key` now hold dimension ids
    rather than display orders.
  - **No reporting tables in between.** The drop and the rebuild are not one transaction, so
    upgrade outside reporting hours.
- **Database passwords are required.** Survey and FHHS no longer have built-in passwords. Set
  `ELICIT_DB_PASSWORD` and `ELICIT_OWNER_DB_PASSWORD` (or
  `quarkus.datasource.password` and `quarkus.datasource.owner.password`). Without them a
  module logs `no password was provided`, retries for about 8 minutes, then exits.
- **No seeded survey or department on a new install.** The Family History Survey arrives by
  importing `FHHS/family-history-survey.elicit` in Admin's Apply Survey Definition. An
  administrator's first sign-in on a new database asks them to create a department first
  (Admin UC-028). Existing databases keep their "Testing Department".

### Access codes (formerly "token")

- **Database:** `survey.respondents.token` is now `access_code`. The `survey.status` view's
  column is renamed to match.
- **Configuration:** `token.autoRegister` is now `accessCode.autoRegister`. The old key is
  ignored.
- **Email templates:** `<TOKEN>` is now `<ACCESS_CODE>`. Stored templates are converted
  automatically.
- **FHHS SFTP XML template:** `{Token}` is now `{AccessCode}`. This template comes from
  deployment configuration, so change it by hand.
- **Integration API:** `/api/secured/add/subject`, `/add/subjects` and `/add/csv` return
  `status.accessCode` instead of `status.token`.
- **Admin links:** the subject edit route takes `?accessCode=` instead of `?token=`.
- **Branding:** `.elicit-token` is now `.elicit-access-code`, and `--brand-token-bg` and
  `--brand-token-text` are now `--brand-access-code-bg` and `--brand-access-code-text`.
- **Respondent sessions:** respondents who are mid-survey during the upgrade must sign in again.
  Their answers are kept.

### FHHS

- **SFTP delivery is off by default.** Set `family.history.sftp.enabled=true` to keep sending
  reports to the SFTP destination. Without it, reports silently stop being delivered.
- **The SFTP server's host key is verified.** Set `family.history.sftp.knownHosts` to either
  `known_hosts` lines (from `ssh-keyscan -p <port> <host>`) or the path of a known_hosts file.
  If it is unset, the connection is refused. `family.history.sftp.strictHostKeyChecking=false`
  turns the check off; use that only for local development.
- **FHHS no longer installs the Family History Survey.** Import it in Admin > Apply Survey
  Definition from `FHHS/family-history-survey.elicit`. Until the import is applied:
  - FHHS still starts, but `/q/health/ready` reports it as not ready.
  - Every report request gets HTTP 503, with a message saying the survey must be imported.

  No restart is needed afterwards: FHHS becomes ready on its next health check.

### Outbound connections

- **TLS certificates are verified.** `quarkus.tls.trust-all` is no longer set. If a report
  service, post-survey action or identity provider uses a private CA, add it with
  `quarkus.tls.trust-store.pem.certs`.
- **Admin needs Survey's address.** Admin calls Survey to build reporting schemas and to print
  the built-in respondent summary. Set `elicit.survey.url`; the default `http://survey:8080` only
  resolves inside Docker Compose. Survey's `/api` paths (other than `/api/pdf/download`) are meant
  for Admin only: do not expose them publicly. For the GKE campsites, see the
  `survey_campsite` and `admin_campsite` merge requests.

## New features

### Survey

- **Versioned survey structure.** Kimball Type 2 SCD with durable, portable keys. Structure is
  resolved as of the respondent's first access (UC-002).
- **Per-survey reporting.** A per-survey reporting star schema, built on demand through
  `POST /api/etl/build?survey=<key>` and renamed through
  `POST /api/etl/schema/<key>/rename?name=` (UC-008). `dim_date` now runs through 2050, and its
  weekend flag is fixed.
- **Interface languages from a mount.** The image carries English only. Survey reads every other
  language from `translations_<tag>.properties` in `<i18n.file.system.path>/survey/`. A mounted file
  may hold only the texts it changes; the rest fall back to English. The settings:
  - `i18n.offered.locales` offers fewer languages than are mounted.
  - `i18n-config.json` at the mount root sets a language's text direction and size.
  - `i18n.direction.<tag>` and `i18n.font-scale.<tag>` override the direction and size for one
    deployment.

  With nothing mounted, Survey offers English only and shows no language selector (UC-007).
- **Translated survey content.** Survey content is shown in the respondent's language, wherever
  the survey publishes a translation and the site offers the language (UC-009). The date picker's
  calendar follows the language.
- **Repeats.** A question or section can repeat once for each item selected.
- **Built-in respondent report.** A respondent report rendered in process and over HTTP (UC-014).
  Report marks (`survey.report_items`) choose what it shows (UC-013).
- **Progress stamps.** Respondent progress is recorded in `answers.presented_dt`,
  `respondents.last_activity_dt`, and `answers.saved_dt`, which is now set only when the
  respondent changes a value (UC-012).
- **Reports page skipped** when a survey lists no reports.
- **ETL switch.** `elicit.etl.enabled=false` turns the reporting ETL off on preview instances.
- **Startup diagnostics** are logged when the service starts.

### Admin

- **Participation page (UC-031).** It shows:
  - live counts and the questions marked for reporting;
  - charts, drop-off, stalled respondents and time per step;
  - small-cell suppression;
  - CSV and PDF export.

  Two settings tune it: `elicit.participation.small-cell` (default 5) and
  `elicit.participation.stalled-days` (default 14).
- **System section.** Shows the running version, both database connections, each module's
  migrations, brand resolution and mail settings, with a test email button. It also checks that
  every outbound dependency can be reached, and its OIDC page shows the current sign-in's roles.
- **Survey definitions.**
  - Update Survey Definition applies a revised `.elicit` over an existing survey, including
    retirements and content translations (UC-017).
  - Export Survey Definition writes a survey back out as a `.elicit` file.
  - When a definition file is refused, the console shows why.
  - Applying a definition rebuilds that survey's reporting schema.
- **Reporting schema rename** from the console.
- **Portable exports.** Respondent export and import work across deployments and carry the
  progress stamps.
- **Departments.** A department assignment is required (UC-028).
- **Registration.** RegisterView lets the administrator choose which survey a new subject is
  registered on.
- **Administrator's manual** inside the application (UC-029).
- **Fixes:**
  - Search Subjects shows every row of the page.
  - Access code generation no longer retries forever.
  - A fresh database with no survey can start and accept a definition.

### FHHS

- **Survey by import.** FHHS takes the Family History Survey by import and refuses service until
  it arrives (UC-005). It reads the survey's own reporting schema, whatever it is named.
- **Verified SFTP delivery** (NFR-007, UC-004 BR-006).
- **Survey definition fixes:**
  - Every placeholder is delimited.
  - `{S1}` on the Mother and Father steps is filled from an answer.
  - The defaultless placeholders get an empty default.

### Pedigree

- No functional changes. CI now builds the image and smoke-tests `/healthz` and `/svg`.

### Platform (this repository)

- **Installation manual** (`docs/manual/`, a PDF). It is built with the images and checked
  against the modules' configuration properties, so a drifted reference fails the build.
- **Curated translations** in `elicit-i18n/`: Spanish and Arabic for Survey and Admin, plus
  `i18n-config.json`. Docker Compose mounts it at `/opt/i18n`.
- `buildDockerImages.sh` builds all modules and the manual in parallel. Before building, it checks
  that the images carry English only and that `elicit-i18n/` gives Survey and Admin the same
  languages.
- `status.sh` probes each service's health endpoint and says why one is not ready.
- `resetDatabase.sh V2|V3` resets the local database for brownfield or greenfield test runs.
- The local Docker Compose stack starts FHHS after Admin, so their first migrations do not
  collide.

## Security fixes

- **TLS trust-all removed** from Survey and Admin. Outbound HTTPS now verifies certificates.
- **Timeouts on outbound calls.** Survey's post-survey actions and report services get a
  5-second connect timeout and a 60-second answer timeout. A service that never answers can no
  longer hold a respondent's request forever.
- **SVG rendering hardened.** Apache Batik is upgraded from 1.16 to 1.20 (CVE-2022-44729 and
  CVE-2022-44730), and PDF rendering now refuses external resources and scripts in SVG.
- **SFTP.** FHHS moves from the unmaintained `com.jcraft:jsch:0.1.55` to
  `com.github.mwiede:jsch:2.28.8` and verifies the server's host key.
- **No default database passwords** in Survey or FHHS.

## Platform and dependencies

- Java 25, Quarkus 3.40.1.1 LTS (was 3.39.2), and Vaadin 25.3.4 (was 25.2.7).
- Images are built with Quarkus packaging. Tests run during the image build, and `vaadin-dev`
  is kept out of the production image.
- Every repository's CI now runs on pull requests, and `main` and `V3` change only through a
  pull request whose CI passed.
- Survey's build fails if line coverage drops below 70%. Survey, Admin and FHHS run Pitest
  mutation testing over their plain unit tests.

## Upgrading from 2.x

1. **Back up the database.** There is no rollback other than restoring it.
2. **Change the configuration** listed under [Breaking changes](#breaking-changes):
   - database passwords;
   - `accessCode.autoRegister`;
   - the FHHS SFTP settings and `{AccessCode}`;
   - `elicit.survey.url` for Admin;
   - any private CA trust store;
   - any custom brand CSS;
   - the translations mount, if the site offers languages other than English: mount
     `elicit-i18n/` and set `i18n.file.system.path` for Survey and Admin.
3. **Upgrade Survey, Admin and FHHS together.** Start Survey and wait until it is ready, then
   start Admin, then FHHS.
4. **Verify the reporting schemas.**
   `select name, report_schema from survey.surveys;` should name a schema for every survey, and
   `report_family_history_survey.dim_step` should have 15 rows for the Family History Survey.
5. **Tell report consumers** about the new schema name and the new reporting ids.

If the database also moves to a host with a different glibc, PostgreSQL warns about a
collation version mismatch. Fix it with `REINDEX DATABASE` and
`ALTER DATABASE … REFRESH COLLATION VERSION` before starting the applications (see
`DeploymentScript.md`).

## New installation

Follow the installation manual (`docs/manual/elicit-installation-manual.pdf`). Then, in order:

1. Start the stack.
2. Sign in as an administrator and create a department.
3. Apply `FHHS/family-history-survey.elicit` in Admin > Apply Survey Definition.

## Known issues and limitations

- **Temporary upgrade code.** The V2-to-V3 upgrade path (`ManualSchemaMigrator` and
  `db/migration-v3/` in Survey and FHHS) is temporary. It will be removed in a later release,
  once every deployment has upgraded.
- **FHHS applies its V0.0.9 migration on its second start** after a brownfield upgrade. It
  needs no action, and the first start is healthy.
- **Prometheus is not part of the local Compose stack.** Jaeger collects traces only.
- **Author** (the authoring tool) is a separate private repository and is not part of this
  release.
